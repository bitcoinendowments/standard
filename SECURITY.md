# Security

## What belongs here

This repository holds documents, schemas, and test vectors. It does not hold custody software and it holds no funds.

Two different kinds of report are relevant:

**A flaw in the standard.** A requirement that is unsafe, a verification label that overstates what backs a claim, or a procedure with an exploitable gap. Open a public issue. This class of problem is safer discussed in the open, because deployments need to know.

**A vulnerability affecting a live deployment.** Do not open a public issue. Contact the affected deployment directly through the contact in its evidence package. If the flaw originates in this standard, report it to the maintainers privately first, and we will coordinate a public issue and a proposal once affected deployments have been notified.

## Contact

Private reports go to the maintainers listed in `GOVERNANCE.md`.

## What we do not do

We do not audit deployments, run a bug bounty, or issue advisories on behalf of any organization. A deployment's security is the responsibility of the organization operating it.
