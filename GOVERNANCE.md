# Governance

## Who decides

This standard is stewarded by Bitcoin Chiang Mai Ltd Co.

| Name | Role |
|------|------|
| Jimmy Kostro | Maintainer. Approves or rejects changes |

A maintainer decides what is merged. An author wrote part of the work. The roles are separate and either may exist without the other, and this table lists maintainers.

Additional maintainers are added by the existing maintainers, in a pull request that records the reason.

## The decision rule

Editorial and clarification changes are merged by any maintainer after review.

Normative changes require a proposal under `CONTRIBUTING.md`, a public comment period of at least thirty days, and agreement among the maintainers. Where maintainers disagree, the change does not merge. A blocked proposal stays open with the disagreement recorded in the proposal file, so that anyone reading later can see what was contested rather than only what was decided.

Dissent is recorded, never deleted.

At release 0.1.0 there is one maintainer, so the comment period, not an internal vote, is the real check on a normative change. Anyone reading this should weigh it accordingly, and the answer to a maintainer who decides badly is the fork this license already permits.

## Conflicts of interest

The maintainers of this standard must not serve as guardians for any deployment that adopts it, under BES 0001 §4.5. Any maintainer with an interest in a specific deployment must disclose it in the proposal thread and abstain from decisions that affect that deployment's conformance.

## Forking

Forking this repository is legitimate, expected, and not a hostile act.

The license requires no permission, no attribution, and no notice. If you disagree with a decision made here, the correct response is to fork and to say publicly what you changed and why. A standard that treats a fork as betrayal is asking adopters to accept a relationship obligation, and that obligation is exactly what this project exists to avoid.

The name of the project is not restricted.

## If the maintainers stop

Every document here is released under CC0 1.0 and Apache 2.0. If this repository goes quiet, is abandoned, or is deleted, three things remain true:

1. Every existing adopter is unaffected. Nothing is adopted by reference, and every deployment holds its own documents.
2. Anyone may continue the work, under this name or another, without asking.
3. No release already published can be changed, because tags are immutable and copies are permitted without restriction.

Continuity of this project is not a dependency for anyone who has adopted the standard. That is deliberate.
